## 3. 영상 관찰 — 근본 문제 발견

사용자 영상 관찰:
1. **다리가 거미처럼 벌어짐** — 개보다 거미에 가까운 형상
2. **다리 부착점이 몸체보다 위에 위치** — 다리가 바깥으로 벌어지는 원인
3. **보폭이 정상의 ~20%** — 다리를 끝까지 내딛지 않음
4. **넘어짐 회피 학습** — 보수적 셔플링 패턴

## 4. URDF 구조 분석 — 근본 원인

### 다리 부착점 (어깨)
| 항목 | 값 | 문제 |
|------|-----|------|
| 어깨 부착점 간격 (Y축) | ±0.036m (총 7.2cm) | 몸체 너비(11cm)의 66% — **너무 좁음** |
| 몸체 충돌 박스 | 0.14m × 0.11m × 0.07m | 다리보다 넓음 |
| 어깨 관절 범위 | -0.548 ~ +0.548 rad (±31.4°) | 좁은 부착점에서 이 범위 = 벌어짐 |
| 기본 어깨 각도 | -0.04 rad | 거의 중립 |

### 기본 관절 각도
```
Front/Rear Left & Right:
- shoulder: -0.04 rad    (약간 안쪽 기울임)
- leg:      -0.71 rad    (뒤로 구부림, ~-40.7°)
- foot:     +1.31 rad    (~75.1° 신장)
```

### 구조적 문제
좁은 부착점(7.2cm)에서 몸체(11cm)를 지탱하려면 다리를 벌릴 수밖에 없음.
높이 목표(0.22~0.24m)를 달성하려면 더 벌려야 함.
**거미 형상은 물리적으로 필연적**.

## 6. 연구 조사 — 성공한 프레임워크의 해법

### 벌어짐 방지
| 접근법 | 출처 | 핵심 |
|--------|------|------|
| **dof_pos_dev 패널티** | legged_gym (ETH RSL) | 기본 관절각에서 벗어나면 패널티 → 벌어짐 방지의 핵심 메커니즘 |
| **Barrier-based style** | arXiv 2409.15780 | 물리 한계보다 좁은 소프트 한계로 스플레이 원천 차단 |
| **PALo** | arXiv 2503.04462 | front/hind 별도 자세 제약 → 자세 유지하며 운동 |

### 보폭 확대
| 접근법 | 출처 | 핵심 |
|--------|------|------|
| **foot clearance reward** | Walk These Ways (CMU) | swing 중 발 높이 패널티 → 들어야 하니 보폭 증가 |
| **velocity-dependent stride** | 공통 | 속도 범위를 좁게 → 대칭 보행 촉진 |
| **propulsion reward** | 현재 프로젝트 | stance 중 뒤로 미는 속도 보상 → 직접적 보폭 유도 |

### 보수적 보행 해결
| 접근법 | 출처 | 핵심 |
|--------|------|------|
| **2단계 학습** | arXiv 2309.09682 | 1단계: 걷기, 2단계: 스타일/민첩성 |
| **velocity curriculum** | 공통 | 저속부터 시작 → "안 움직이면 안전" 방지 |
| **최소 속도 패널티** | 공통 | 이동 명령 시 최소 속도 미달 패널티 |

## 7. V33 방향 제안

### A. 어깨 중립 패널티 대폭 강화
- 현재 `shoulder_neutral`이 있지만 weight 부족
- legged_gym: dof_pos_dev가 주요 보상의 10~50% 수준
- **어깨 각도를 기본값(-0.04)에 강하게 고정** → 벌어짐 차단

### B. 보폭 관련 보상 재설계
- `foot_extension` 패널티 완화 또는 제거 — 보폭 확대 허용
- `stride_length` 보상 활성화 (현재 curriculum으로 0)
- 최소 보폭 패널티 추가 — 셔플링 방지

### C. 높이 목표 재검토
- 현재 0.22~0.24m이 좁은 부착점에서 너무 높을 수 있음
- 약간 낮추면 벌림 없이도 안정 가능

### D. 보상 정리 (50+ → 20~25개)
- 교훈 #10: 50개+ 보상은 상호작용 예측 불가
- 성공한 프레임워크는 15~20개
- 충돌하는 보상 제거, 핵심만 남기기

## 8. 프로젝트 교훈 업데이트 (V1~V32.1)

1. **output=0 reward는 weight를 올려도 0** — band 밖이면 gradient 소멸
2. **패널티만으로는 고착된 local optimum 탈출 불가** — 인센티브 구조 변경 필요
3. **비대칭 보호는 붕괴를 이동시킬 뿐** — 전체 다리에 동일 기준 적용
4. **critic reset + 대규모 reward 변경 = 발산** — from-scratch가 안전
5. **물리적 비대칭이 있으면 reward로 극복 불가** — 초기 자세 대칭이 전제조건
6. **특정 행동의 부재는 패널티로 해결 불가** — 해당 행동에 대한 명시적 보상이 필요
7. **step-level alternation은 역할 분리를 보상** — temporal alternation과 다름
8. **contact-level 패널티는 대각 역할 분리를 유발** — joint-level 접근이 필요
9. **다리별 전용 보상(front_*, rear_*)은 역할 분리 유발** — 4발 공통 보상이 안전 ★ V31.2
10. **보상 50개+는 항목 간 상호작용 예측 불가** — 성공한 프레임워크는 15~20개 ★ 연구조사
11. **Gait 패턴은 "발견"보다 "지시"가 안정적** — phase clock/CPG 구조적 강제 ★ 연구조사
12. **한 번에 하나만 변경** — 동시에 여러 변경은 실패 원인 분리 불가 ★ V32
