## 1. V16: diagonal_joint_coupling_reward (2026-02-27 ~ 03-03)

### 배경
- V12까지의 접촉 센서 기반 trot 보상 → 로봇이 **미세진동으로 속임**
- **접촉 센서 보상은 악용 가능** (Lesson #1)
- 키네마틱(관절 속도) 기반으로 전환 결정

### 핵심 보상: `diagonal_joint_coupling_reward`
```python
def diagonal_joint_coupling_reward(env, asset_cfg, ...):
    """대각선 다리 쌍의 관절 속도 상관도 측정"""
    # FL↔RR, FR↔RL 관절 속도 상관계수 계산
    # trot gait: 대각선 다리가 동시에 움직임
    # corr(FL_vel, RR_vel) + corr(FR_vel, RL_vel) → 높을수록 trot
```

### 원리
| 대각선 쌍 | Trot일 때 | Pace일 때 | Bound일 때 |
|-----------|:---------:|:---------:|:---------:|
| FL ↔ RR | 동위상 (상관↑) | 역위상 (상관↓) | 없음 |
| FR ↔ RL | 동위상 (상관↑) | 역위상 (상관↓) | 없음 |

- 접촉이 아닌 **관절 움직임 패턴** 자체를 측정
- 미세진동으로는 높은 상관도를 만들기 어려움

### 학습 진행
| 폴더 | iter 범위 | 비고 |
|------|-----------|------|
| `2026-02-27_...` | 0→7,600 | V16 시작 (이동으로 중단) |
| `2026-03-03_...` | 7,600→10,800 | V16 재개 |

### 결과
- ✅ 대각선 커플링 보상이 정상적으로 작동
- ✅ 앞다리의 트롯 패턴 일부 관찰
- ⚠️ 여전히 "진정한 보행 주기"는 미확인

## 2. V17: 걸음주기·보폭·행동률 추가 (2026-03-04)

### 변경 사항

#### 새 보상 함수
| 보상 | 목적 | 가중치 |
|------|------|:------:|
| `gait_cycle_period_reward` | 걸음주기 0.3~0.5s 유도 | 15.0 |
| `stride_length_reward` | 보폭 0.06m 유도 | 12.0 |
| `action_rate_l2_clamped` | 행동 변화율 제한 | -1.5 |

#### 기존 보상 강화
| 보상 | 변경 | 의도 |
|------|------|------|
| `dof_acc_l2` | 가중치 증가 | 관절 가속도 제한 강화 |
| `joint_vel_l2` | 가중치 증가 | 관절 속도 제한 강화 |
| velocity 범위 | 확대 | 더 빠른 속도 유도 |

### `gait_cycle_period_reward` 구조 (rewards.py lines 918-1018)
```
① 같은 발의 연속 접지 이벤트(touchdown) 2회 이상 추적
② 접지 간격 = period (초)
③ period > 0인 경우에만 보상 계산
④ 보상 = exp(-(period - target)² / (2 × sigma²))
⑤ vel_gate = clamp(vel_x / min_vel, 0, 1) 곱하기
⑥ target: 0.3~0.5s (uniform 범위)
```

### `stride_length_reward` 구조 (rewards.py lines 1019-1115)
```
① 각 발의 liftoff 시점에 발 위치 저장
② touchdown 시점에 발 위치 측정
③ stride = sqrt((x₂-x₁)² + (y₂-y₁)²) — XY 평면 이동거리
④ stride > 0.001 (1mm) 필터
⑤ 보상 = exp(-(stride - target)² / (2 × sigma²))
⑥ vel_gate 곱하기
⑦ target: 0.06m
```

## 3. V17.1: feet_air_time 완화 (2026-03-05)

### 변경
- `feet_air_time` reward의 threshold 완화
- 뒷다리가 조금이라도 공중에 뜨면 보상 부여

### 학습 결과 (iter 5,104)

| 지표 | 값 | 평가 |
|------|:---:|------|
| **Mean Reward** | **-54.2** | 마이너스 → 페널티 > 보상 |
| forward_velocity | 0.009 m/s | 거의 정지 |
| standing_height | 높음 | 서기 보상에 집착 |
| gait_cycle_period | 0.0 | 유효한 걸음주기 없음 |
| stride_length | 0.0 | 보폭 없음 |
| bad_orientation | 100% | 모든 에피소드 orientation 벌어짐 |
| diagonal_coupling | 감소 | 대각선 커플링 퇴화 |

### "정지 함정" (Stillness Trap) 진단

```
PPO 최적화 관점에서의 로봇 전략:
  
  서기(+40)가 최대 보상 → 서기에 집중
  움직이면 페널티 위험: dof_acc(-), joint_vel(-), action_rate(-)
  → "가만히 서있기"가 최적 전략
  → gait_cycle=0, stride=0 → 가중치×0 = 0 (보상 무시)
  → 전진=0 → 모든 vel_gated 보상도 0
  → 순수 standing_height만 수집하는 전략 확립
```

### 핵심 문제: 너무 많은 동시 페널티
- V17에서 추가된 `dof_acc_l2`, `joint_vel_l2`, `action_rate_l2_clamped` 모두 "움직이면 벌점"
- standing_height(+40)이 "안 움직여도 받는 보상"
- **합리적 PPO 에이전트는 당연히 안 움직임**

## 4. V17.1 → V18 전환 결정

### 문제 정리
1. 너무 많은 동시 페널티 → 정지 함정
2. standing_height가 지배적(weight=40) → 서기만 해도 큰 보상
3. gait_cycle/stride가 0이면 해당 보상이 완전 무시됨
4. 단일 가중치 세트로는 "서기→걷기→트롯" 단계 유도 불가

### 해결 방향: 3-Phase 커리큘럼
> Phase 1: 서기 학습 (standing 중심, 페널티 약함)  
> Phase 2: 걷기 전환 (standing 감소, 걸음 보상 증가)  
> Phase 3: 트롯 완성 (gait_cycle/stride 최대, standing 최소)

→ **V18: 3-Phase Curriculum** 으로 진화

## 5. 이 시기의 핵심 교훈

| 교훈 | 근거 |
|------|------|
| **접촉 센서 보상은 악용 가능** | V12까지 미세진동으로 속임 → V16 키네마틱 전환 |
| **관절 속도 기반이 더 robust** | diagonal_coupling이 패턴 직접 측정 |
| **너무 많은 동시 페널티 = 정지 함정** | V17.1의 reward=-54.2, 전진 0.009 m/s |
| **지배적 보상이 다른 것을 가림** | standing_height(40) >> 나머지 |
| **단일 가중치 세트의 한계** | 서기·걷기·뛰기를 동시에 유도할 수 없음 |
| **From scratch PPO 설정 안정** | V15d의 gamma=0.97, clip=0.1이 V16/V17에서도 유효 |
