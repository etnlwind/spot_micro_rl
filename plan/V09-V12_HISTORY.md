## 2. V10: rear_alternation 추가 (2026-02-22)

### 시도
뒷다리 교대 스윙을 직접 유도하는 보상 추가:
```python
rear_alternation_reward:
  weight: 150.0
  # 뒷다리 두 발이 교대로 접지/비접지하면 보상
```

### 학습 체인
| 폴더 | iter | 비고 |
|------|------|------|
| `2026-02-22_13-11-38` | 11,000→16,500 | V10 학습 |

### 결과
- ❌ **"토큰 교대"** — 뒷다리를 살짝 들었다 즉시 내려놓기
- 접촉 센서에서는 "교대"로 감지되지만, 실제 보폭은 제로
- **교훈: 접촉 센서만으로는 진짜 걸음걸이를 강제할 수 없음**

## 3. V11: rear_both_ground 페널티 추가 (2026-02-22~23)

### 시도
뒷다리 두 발이 동시에 접지하면 페널티:
```python

  weight: -200.0
  # RL+RR 동시 접지 → 페널티 1.0
```

### 학습 체인
| 폴더 | iter | 비고 |
|------|------|------|
| `2026-02-22_23-19-25` | 16,500→21,200 | V11 학습 |

### 결과
- ❌ 발을 들긴 하지만 **제자리에서 올렸다 내림** (보폭 없음)
- rear_both_ground 페널티를 피하기 위해 한 발만 들기 하지만 진행 방향으로 안 움직임

## 5. 핵심 발견: 접촉 센서의 한계

```
V10: 교대 보상 → "토큰 교대" (살짝 들었다 내림)
V11: + 동시접지 페널티 → "제자리 들기" (보폭 없음)
V12: + 높이×속도 곱 → "미세 진동" (접촉 센서 속임)
```

**결론**: 접촉 센서(contact forces) 기반 보상만으로는 뒷다리 실제 보행을 강제할 수 없음.
→ V16에서 **키네마틱(joint velocity) 기반**으로 전환하는 근거가 됨.

---

## 6. 이 시기의 교훈

| 교훈 | 근거 |
|------|------|
| **접촉 센서 보상은 뒷다리가 속일 수 있음** | V10~V12 전부 미세진동으로 우회 |
| **당근+채찍 병행 필요** | alternation(당근)만으로는 부족, both_ground(채찍)도 추가 |
| **곱셈 보상(A×B)이 효과적** | "둘 다 해야" 조건 표현, 하지만 접촉 센서의 한계 |
| **min-heavy 결합 (0.4mean+0.6min)** | 최악 성분을 견인하는 효과 |
| **30K iter도 부족할 수 있음** | structural barrier는 시간으로 해결 불가 |
