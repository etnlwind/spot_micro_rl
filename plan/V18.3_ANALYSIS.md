## 2. V18.3 핵심 변경: `stance_propulsion_reward`

### 2.1 문제 인식

기존 보상 체계의 구조적 공백:

| 보상 | 위상 | 측정 대상 | 한계 |
|------|------|-----------|------|
| `swing_stride_reward` | 스윙 (공중) | 발 전방 속도 | 공중 동작만 보상 |
| `rear_forward_stride_reward` | 스윙 (공중) | 높이 × 전방속도 | 공중 동작만 보상 |
| `forward_velocity` | 전체 | 동체 전진 속도 | 결과만 봄, 메커니즘 無 |
| **`stance_propulsion` (NEW)** | **스탠스 (접지)** | **바닥 밀기 힘** | **추진 메커니즘 직접 보상** |

**보행 사이클의 완전한 구조**:
```
① 스탠스(접지) → 발이 바닥에 고정, 다리가 뒤로 밀어서 동체 전진  ← NEW!
② 토오프(이륙) → 발이 지면에서 이탈
③ 스윙(공중) → 발을 앞으로 내밈                               ← 기존 보상
④ 착지(터치다운) → 사이클 반복
```

### 2.2 측정 원리

```python
# 발의 동체-상대 heading 속도
relative_vel = foot_world_vel(heading) - body_world_vel(heading)

# 음수 = 발이 동체 대비 뒤로 이동 = 바닥을 밀고 있음
push_magnitude = clamp(-relative_vel, min=0)

# 접지 중인 발만 보상 (스탠스 마스크)
reward = push_magnitude * stance_mask / num_stance_feet
```

이것은 **실제 물리적 보행의 핵심 메커니즘**:
- 발이 바닥에 닿은 상태에서 → 발은 지면에 고정(마찰)
- 다리 관절이 뒤로 구동 → 동체가 앞으로 이동
- 이때 발의 월드 속도 ≈ 0, 동체 속도 > 0 → relative_vel < 0 → 보상!

### 2.3 Phase별 가중치

| Phase | `stance_propulsion` | 의미 |
|:---:|:---:|------|
| 1 (STAND, 0~2000) | **8.0** | 초기부터 밀기 학습 유도 |
| 2 (WALK, 2000~6000) | **15.0** | 보행 시 추진 강화 |
| 3 (TROT, 6000+) | **20.0** | 최대 추진 보상 |

### 3.2 치명적 발견: 커리큘럼 Phase 고착 버그

`reward_weight_curriculum`은 `common_step_counter`를 사용하는데, 이것은 **프로세스 재시작 시 0으로 리셋**됩니다.

```
슈퍼바이저 3시간 주기 = ~1400 iter/cycle
Phase 2 전환 = iter 2000 필요
→ 매 사이클마다 Phase 1에서 시작 → Phase 2 도달 직전에 재시작
→ 훈련 내내 Phase 1만 적용됨!
```

**증거**:
- `gait_cycle_period` = 0.000 (전 구간) ← Phase 1에서 가중치=0
- `stride_length` = 0.000 (전 구간) ← Phase 1에서 가중치=0
- `standing_height` = 0.25 (Phase 1의 40.0 가중치 기준 → 낮지만, Phase 2의 8.0이었다면 더 낮았을 것)

### 3.4 stance_propulsion = 0.002 원인 분석

stance_propulsion이 거의 0인 이유:
1. **Phase 1 가중치 8.0이지만**, 보상값 자체가 0.002 → 실제 기여 = 0.016 (미미)
2. **가능한 원인**: 현재 로봇이 "미끄러지듯 전진"하는 상태 — 발이 바닥을 밀지 않고, 관성/경사/진동으로 움직임
3. **또는**: 발이 접지 시 거의 멈춰있어서 동체 상대 속도가 매우 작음 → 보상 신호 미약
4. 이 보상이 효과를 발휘하려면 **Phase 2 이상의 가중치(15~20)**와 **충분한 학습 시간**이 필요

### 3.5 종합 평가

**긍정적**:
- V18.2의 진동 억제가 완벽히 작동 (joint_oscillation -3.25 → -0.72)
- 전진 속도, 트롯 패턴 등 기본 보행 지표 양호
- V18.1의 "서기 극대화" 문제 해결됨

**문제점**:
- **커리큘럼 Phase가 실제로 전환되지 않았음** (슈퍼바이저 재시작 문제)
- stance_propulsion이 효과를 입증하지 못함 (Phase 1 가중치에서는 신호 미약)
- rear_alternation이 여전히 0에 가까움 (뒷다리 좌우 교대 없음)
- gait_cycle, stride가 한 번도 활성화되지 않음

## 5. 이전 실험에서 배운 교훈 (적용됨)

1. **슈퍼바이저 + 커리큘럼 비호환** — common_step_counter 리셋 문제. 커리큘럼 사용 시 슈퍼바이저 끄기.
2. **진동 억제가 효과적** — joint_oscillation 페널티가 V18.2→V18.3에서 -3.25→-0.72로 개선 입증.
3. **"결과"가 아닌 "메커니즘" 보상이 중요** — forward_velocity(결과)만으로는 올바른 보행을 학습 못함. stance_propulsion(원인)을 추가.
4. **standing_height 감소 효과** — V18.1의 13.68 → V18.2/V18.3의 0.25로 서기 극대화 문제 해결.
5. **Phase 1은 2000 iter면 충분** — 500 iter 시점부터 이미 안정 서기 달성.
