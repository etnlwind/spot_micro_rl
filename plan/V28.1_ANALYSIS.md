## 4. 붕괴 패턴 분석

### 4.1 타임라인

- **iter 1000**: 4발 완벽한 상태. validity pass, rear_diff 0.034, umin 0.921
- **iter 1002**: run 재기동 직후 생존률 급락 (정상적 checkpoint-reeval 패턴)
- **iter 1102**: RR contact 0.355로 하락 시작. rear_diff 0.217 — 이미 경보 수준
- **iter 1201~1502**: RL은 계속 상승(0.561→0.701), RR은 계속 하락(0.277→0.259)

### 4.2 V28 vs V28.1 collapse 패턴 비교

| 버전 | collapse 축 | 발생 시점 | 회복 여부 |
|------|------------|-----------|-----------|
| V28 | **RL** collapse | iter 901~1000 | ✗ (run 재기동 후에도 RL ≈ 0) |
| V28.1 | **RR** collapse | iter 1002~1102 (run 재기동 후) | ✗ (계속 하락) |

collapse 축이 RL → RR로 이동했다. 이는 rear pair 중 한 쪽을 희생하는 local optimum이 구조적으로 존재함을 시사한다.

### 4.3 reward 역설적 상승

| 구간 | RL | RR | reward |
|------|-----|-----|--------|
| iter 1000 (4발 건강) | 0.448 | 0.483 | 665 |
| iter 1502 (RR 붕괴) | 0.701 | 0.259 | 712 |

RR이 붕괴한 후 reward가 오히려 상승했다. FL/FR/RL 3발이 더 효율적으로 최적화된 것으로 해석된다.

## 5. 실패 원인

### 원인 1. rear_pair_residency_symmetry_penalty 강도 부족
- max weight = -8.0 (iter 600~1000 ramp)
- iter 1502 실제 penalty ≈ -8.0 × (gap 0.45) ≈ **-3.6**
- 3발 exploit 추가 이득(+8~15 추정)을 이기지 못함

### 원인 2. Run 재기동 후 EMA 리셋 사각지대
- `_v281_residency_ema`가 episode 리셋 시 초기화
- run 재기동 시 모든 env EMA = 0 → `rear_pair_residency_symmetry_penalty` = 0
- EMA 워밍업 과정에서 RL EMA가 RR EMA보다 빠르게 올라가고 격차 형성
- 이 격차가 굳어지는 iter 1002~1102 사이에 penalty 미반응

### 원인 3. heartbeat에 residency 지표 없음
- `contact_band_residency_rl/rr`, `rear_pair_residency_gap` 등이 common.py에 없음
- iter 1102에서 이미 rear_diff=0.217이었지만 heartbeat는 "핵심 KPI 5개 양호"로 표시
- 조기 개입 불가능

## 6. V28.1이 실제로 잘한 것

1. **RL residency 유지 완전 달성** — V28에서 iter 1000에 0.146이던 RL contact가 V28.1에서 0.448, 최종 0.701까지 상승
2. **4발 validity pass 달성** — iter 1000에서 처음으로 달성. 이전 모든 버전에서 불가능했던 상태
3. **target-band + cooperation 구조의 안정적 작동 재확인** — V28에서 검증한 구조가 V28.1에서도 유지됨
4. **EMA residency relay 구조 유효성 확인** — iter 200~1000 구간에서 RL을 band 안에 유지하는 데 성공

---

## 7. V28.2로 넘어가는 이유

V28.1은 실패했지만, 다음 이유로 V29가 아닌 V28.2로 간다:

1. 구조 자체가 틀리지 않았다 — iter 1000에서 완벽한 4발 상태 달성
2. 실패 원인이 명확하고 수정 가능하다 — penalty 강화 + EMA 사각지대 보완
3. RL을 살리는 성과를 버릴 필요가 없다 — V28.2는 RR도 같은 수준으로 보호하는 버전

상세 설계: `plan/V28.2_PLAN.md` 참조.
