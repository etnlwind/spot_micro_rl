# V28.3_ANALYSIS.md

## 한 줄 결론
**V28.3은 front contact cap(-10.0)이 앞발 고착 local optimum을 끝내 깨지 못했다.**
실패 원인은 cap 강도 부족이 아니라, `contact_residency` 밴드에 상한이 없어
FL/FR contact 0.83도 최대 residency reward를 받는 구조적 문제였다.
rear pair 대칭(V28.2 달성)은 전 구간 유지됐고, 이 성과는 V29로 계승된다.

## 5. 실패 원인

### 원인 1. contact_residency 밴드에 상한 없음 (구조적 근본 원인)

`per_leg_contact_band_residency_reward` 실제 동작:

```python
in_band = 1.0 if contact_ratio >= 0.20 else 0.0
ema = ema * 0.95 + in_band * 0.05
reward = ema * late_max  # late_max = 4.0
```

FL contact 0.50과 0.83이 동일하게 `in_band=1.0` → EMA ≈ 1.0 → reward ≈ 4.0/step.

contact_residency reward가 앞발 고착에 아무런 불이익을 주지 않는다.
V28.3은 이 구조 위에 외부 패널티(cap)를 얹는 방식이었지만,
내재적 reward가 고착을 지원하는 한 외부 패널티로는 한계가 있었다.

### 원인 2. cap penalty vs residency 이득 — 설계 당시 계산 오류

V28.3 설계 당시 residency 이득 계산:
```
FL residency EMA(0.941) × late_max(4.0) ≈ +3.76/step
FL 0.65로 하락 시: 0.65 × 4.0 ≈ +2.60/step
→ 이득 차이: -1.16/step
→ cap penalty: -10.0 × gap(0.19) = -1.90/step > 1.16 → "충분"
```

실제 상황:
```
FL contact 0.83 → in_band=1.0 → EMA ≈ 1.0 → reward = 4.0/step (EMA 기반)
FL contact 0.65 → in_band=1.0 → EMA ≈ 1.0 → reward = 4.0/step (동일!)
```

EMA가 1.0에 수렴해 있는 한 FL contact를 0.83→0.65로 낮춰도 residency reward 손실이 없다.
따라서 cap에 저항하는 실질적 이득은 +1.16/step이 아니라 **0/step** — 설계 당시 계산이 틀렸다.

실제 cap 저항의 원인은 residency가 아니라:
- trot_gait reward(180.0): 기존 패턴 유지하면 자동으로 높은 reward
- forward_velocity reward: 앞발 고정 상태에서도 전진이 가능

### 원인 3. 학습 패턴 고착 후 외부 패널티의 한계

iter 300~400 사이에 이미 FL/FR이 0.74~0.79로 고착됐다.
이 시점에서 정책 네트워크는 front-heavy 보행을 "정상"으로 학습했다.

cap ramp가 iter 700에 시작했을 때, 정책은 이미 수백 iter 동안 해당 패턴으로 최적화된 상태.
외부 패널티 하나로 이미 형성된 보행 패턴을 깨는 것은 gradient 기반 학습에서 매우 어렵다.

## 6. V28.3이 실제로 잘한 것

1. **rear pair 대칭 완전 유지** — V28.2에서 달성한 rear_usage_diff 0.012가 V28.3 전 구간에서 유지됨. rear 안정성 구조가 강건함이 증명됨.

2. **근본 원인 발견** — contact_residency band_high 부재라는 구조적 문제를 명확히 드러냄. 이는 V29 설계의 핵심 단서가 됨.

3. **외부 패널티 방식의 한계 실증** — "이미 형성된 local optimum에 cap을 추가하는 방식"의 한계를 데이터로 확인. reward 구조 자체를 수정해야 한다는 결론으로 이어짐.

## 9. V29로 넘어가는 이유

V28.3은 실패했지만, 다음 이유로 구조를 근본부터 바꾸는 V29로 간다:

1. **실패 원인이 reward 구조 설계 문제** — contact_residency band_high 부재는 V28 시리즈 전체에 걸친 구조적 결함이었음. 패널티 수치 조정으로는 해결 불가.

2. **외부 패널티 방식 한계 실증** — V28.3에서 cap(-10.0)이 효과 없었으므로 더 강한 cap을 시도하는 것은 의미 없음. 보행 패턴이 이미 굳어진 후에는 외부에서 억제하는 방식이 통하지 않는다.

3. **stride efficiency 철학** — 접지 횟수 대비 이동 거리를 최대화하는 reward 구조로 전환. 앞발 고착이 자연스럽게 손해가 되고 큰 보폭 trot이 자연스럽게 이익이 되도록 설계.

4. **rear pair 성과 보존** — V28.2 달성(rear_usage_diff ≈ 0)을 V29에서도 유지.

상세 설계: `plan/V29_PLAN.md` 참조.
